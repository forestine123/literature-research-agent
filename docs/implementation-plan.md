# 具体实现计划

## 目标与范围

课题面向科研学习中的文献资料搜集与分析，重点研究任务规划、学术工具调用和多文献协同分析。首版面向计算机方向主题、本地单用户、一个学术检索源，每任务5—10篇文本型论文；先以3篇材料验证核心流程。

最终流程为：需求解析→计划→检索筛选→阅读与证据提取→缺口判断与有限补检索→跨文献比较→引用检查→报告与界面。未取得全文时明确标为摘要级材料。

不在首版范围内：模型训练、复杂多Agent协作、OCR及图表完整理解、多用户并发、自动取得全部付费论文。

## 技术决策

| 部分 | 决策 | 落地阶段 |
|---|---|---|
| 语言与依赖 | Python>=3.11、uv、锁文件 | M0 |
| 核心编排 | LangGraph，确定性控制与模型决策分开 | M0基础图，M3扩展 |
| 数据契约 | Pydantic，禁止未知字段，校验数量与空输入 | M0 |
| 模型 | 独立ModelPort适配实际可用接口，不绑定模型名称 | M1 |
| 检索 | 优先验证Semantic Scholar；不可用时评估arXiv适配器 | M2 |
| PDF | PyMuPDF候选，按页及段落保存，增加材料层级 | M2 |
| 状态与产物 | SQLite任务与事件，本地文件保存论文与报告 | M4 |
| 界面 | Streamlit，核心流程独立于页面 | M4 |
| 测试 | pytest、合成工具响应、人工固定论文样本 | M0起持续进行 |

只有LangGraph、Pydantic及开发测试工具已作为依赖安装。HTTP客户端、PDF与界面依赖在对应模块实现时添加并重新锁定，避免依赖存在而功能尚不存在的误解。

## 三人成员安排

| 成员 | 主责 | 模块交付 |
|---|---|---|
| 成员一 | Agent架构、模型适配、规划、提取及综合分析、控制预算 | 模型适配、图节点、结构化结果、核心设计文档 |
| 成员二 | 检索、去重、材料获取、PDF解析与工具测试 | LiteraturePort实现、按页段文档、异常测试及样本记录 |
| 成员三 | 界面、存储整合、导出、人工核验、评测与文档 | 交互页面、任务记录、评测表、报告整稿 |

成员一维护共享契约；成员二、三使用相同结构。契约调整先更新文档及调用方测试。成员二负责工具缺陷，成员三组织结果核验，全体参与联调及技术报告审阅。

## 里程碑与阶段验收

按8周相对排期；实际课程日期待填写。工时150—230人时为原始规划估算，待M1、M2可行性验证后重新估计。

| 阶段 | 时间 | 工作及退出条件 |
|---|---|---|
| M0基础工程 | 第1周 | 无密钥运行合成样例，输出带材料标识与证据的结果；测试通过 |
| M1模型适配 | 第1—2周 | 实际接口成功返回计划和提取结构；格式错、超时、预算耗尽可解释；不把模拟测试作为实测 |
| M2文献工具 | 第2—3周 | 一个源真实检索，3篇文本型论文解析；保留元数据、内容层级与页段；限流、无全文有明确状态 |
| M3核心Agent | 第3—4周 | 主题到报告贯通；由缺口决定有限补检索；比较方法、实验条件及局限；形成中期演示 |
| M4交付界面 | 第5—6周 | 查看任务、进度、引用、错误和导出；刷新不重复启动任务；恢复语义经故障测试确认 |
| M5实验验收 | 第7周 | 3主题固定样本及在线测试分开，完成基线对照、人工支持性审核和成本记录 |
| M6报告交付 | 第8周 | 可复现安装、使用说明、不少于8000字总结报告、演示与成员技术说明 |

## 关键设计

1. 查询默认最多3轮（初始加2轮补充），最多10篇；模型调用及token预算在M1增加，每任务明确耗尽状态。
2. DOI或paper_id去重是当前基础；题名近似、预印本版本合并在M2补充，误合并需测试。
3. 模型输出的证据必须绑定论文和段落；不在原文中的片段排除并记录，不默默保留。
4. 片段匹配只证明存在，语义是否支持结论由独立评测记录。不要用模型自评分充当客观准确率。
5. 计划、阅读层级、使用片段与检索日志可检查，全文文件下载成功不等于全文阅读完成。
6. 先比较实验条件再讨论指标；缺失信息不补造，不同条件的数字不直接排名。

## 外部条件

M1需要可用模型端点、模型名和本地密钥；M2需要学术API网络与可合法获取的论文样本。尚未提供的条件写入任务状态，不假定可用。开发演示可继续使用合成数据，但不得宣传为真实调研成功。
