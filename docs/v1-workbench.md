# 第一版工作台：实现与验收边界

本版按 2026 年 10 月提供的正式选题报告调整范围。早期 M0 文档中的 Streamlit、单来源和 8 周安排属于历史方案；当前采用 FastAPI、Vue 3、LangGraph、SQLite、ChromaDB 与 Python 3.12。实施周期按报告的 12 周规划，不据此推断课程实际截止日期。

## 已实现的系统

1. **SearchAgent**：模型生成关键词与子主题；arXiv、OpenAlex、Semantic Scholar 三个连接器按来源并发、同源串行；年份、排除词、来源与数量筛选；DOI/规范化标题去重；来源合并与关键词相关性排序。arXiv 空结果时进行一次显式记录的宽化查询。
2. **ReadAgent**：摘要相关性筛选；PDF 下载、大小限制、物理页提取、页内合并分块、可定位 Markdown；原文支持的信息提取；Chroma 持久化索引。读取不到全文时允许摘要降级，也可选择“必须全文”使任务暂停等待修复。
3. **AnalyseAgent**：先按维度选择每篇最多20条证据并复核结论和原文，再按子主题提炼证据并进行全局综合；结论绑定证据，缺失信息与补检索查询分别存储。只有尚有论文容量、轮次预算且不是固定上传任务时追加在线检索。
4. **WritingOutlineAgent / WritingAgent**：大纲映射证据；逐节写作，每段有证据 ID；模型审查后最多两轮修订，两轮修订后仍有问题时移除审查明确定位的段落并保留说明；若本节全部不受支持且仍有论文容量和轮次预算，则生成补检索计划并返回检索阶段；否则保存已完成章节并失败退出。无法定位问题段落时也保留检查点并报错。
5. **工作台**：研究输入、文献库、证据索引与片段搜索、运行事件、分阶段 token 用量、Markdown/JSON 导出、Provider 配置与连通性测试、阶段主模型与回退模型、历史任务、停止及恢复。
6. **持久化**：SQLite 保存请求、状态、阶段检查点、事件和配置；本地文件保存 PDF、按页 Markdown、模型请求/响应记录和报告。SSE 支持事件 ID 回放，刷新不创建新任务。启动时将孤儿任务标记为 interrupted，并保留审计事件。

这些是五个职责独立的阶段 Agent，经共享状态编排；不是自由并行协商的多 Agent 社会。图的确定性约束、工具执行与模型推理分别实现。

## 数据与引用

`Paper → Reading.blocks → Evidence → Analysis → Outline → Section`。

证据包含论文 ID、块 ID、物理页码、原文及结论。检查先尝试逐字匹配，再仅规范化空白、Unicode 连字与换行断词，并将匹配位置映射回原始文本。最终保存的 quote 必须真实出现在原文块中；不做模糊语义匹配放行。分析、大纲与正文出现未知证据 ID 时阻止发布报告。

模型审查是辅助检查。引用存在性、模型语义审查、人工语义核验是三个不同层次。系统不宣称消除了幻觉。

## 阅读覆盖和向量检索

- 文本型 PDF，每份最多 30 MB、150 页。输出是按页组织的文本 Markdown，不是版面、表格、公式的无损重建。不包含 OCR。
- 小论文在字符预算内完整送入抽取；长论文选取首尾及检索相关块，最多约 24000 字符，分批处理。界面显示“分析块数 / 全部块数”。全文解析完成不等于完整阅读。
- 默认 `lexical_hash`：512 维稳定词项/双词哈希，使用 Chroma 余弦检索，无需下载模型。这是词项相似度，不宣称具备跨语言语义召回能力。
- 配置 OpenAI 兼容 Embedding Provider 与模型名后使用语义向量。索引名称包含服务和模型配置摘要，防止不同向量空间混用。DeepSeek 生成模型不能直接当作 Embedding 模型。
- 语义 Embedding 的实际效果需提供相应服务后另验收；当前已经验收的是默认词项模式。

## 模型和预算

支持 `openai`、`openai_compat`、`anthropic`、`anthropic_compat`。用户可为每个阶段选择不同 Provider；Provider 独立保存模型名、密钥、超时与输出上限。切换服务地址或协议时必须重新输入密钥，防止已保存凭据被无意发送到其他地址。

DeepSeek 使用 OpenAI 兼容接口。真实验收从其 `/models` 获取可用模型，采用 `deepseek-flash`；为结构化提取关闭其思考模式，避免推理内容耗尽输出额度。模型支持情况以各服务实际返回为准。

每次请求前计入调用次数与保守 token 预留，返回实际 usage 后校正；没有返回 usage 或失败的请求保留预留值。该预算是控制机制，不是精确计费账单。Embedding 用量目前不计入生成模型 token 表。默认最多 80 次调用、300000 token 预算，网络请求均设超时，格式问题和临时服务故障最多重试两次；401 等凭据错误不对同一服务重复重试。

实际 Prompt、schema、模型响应与实际模型名保存于 `data/tasks/<id>/model_calls/`，不包含 API Key。仅模型原始响应成功返回后记录；请求前用量事件会先保存以防重启归零。

## 恢复语义

本版为应用层检查点恢复，不把 `graph.compile()` 描述成已经启用 LangGraph 持久化 checkpointer。

- 检索计划、完整检索阶段、每篇论文完成后的阅读与证据、分析、大纲、每个完整章节均是保存点。
- PDF 下载和解析结果独立缓存；依赖或网络修复后可以复用。
- 某篇论文中途抽取失败时，该论文已发出的模型请求可能在恢复后重做；已完成论文不会重复追加证据。费用也不会因恢复而从累计用量中清零。
- 停止是协作式停止，等待正在进行的网络调用结束，在后续检查边界停止，不立即强制断开外部模型请求。
- 仅支持本地单服务实例、单 uvicorn worker。不要让 CLI 验收脚本和服务进程同时拥有同一任务目录；服务启动对账假设其为任务唯一拥有者。
- 当前不支持任意节点中间指令级恢复或分布式任务调度。

## 开发结构

| 文件 | 职责 |
|---|---|
| `src/litresearch/workbench/schemas.py` | 请求、Provider、论文、证据和模型输出契约 |
| `model.py` | 协议适配、结构检查、重试、回退、预算 |
| `sources.py` | 三源连接器、筛选与去重 |
| `reading.py` / `vectors.py` | PDF、按页分块、向量索引 |
| `engine.py` | 五阶段图、证据校验、检查点、报告 |
| `store.py` | SQLite、事件回放、任务领取与对账 |
| `api.py` | REST、SSE、上传、配置、静态前端 |
| `frontend/src/App.vue` | Vue 3 工作台 |

Paper-Agent 的阶段划分与状态组织、dsh-litresearch 的证据与补检索机制用于设计参考。本版没有复制这两个项目的源码，不把参考项目的测试或效果算作本项目成果。

## 后续课程验收

第一版实测不替代报告中的完整实验：仍需 3 个主题、每主题 5—10 篇固定论文、同模型同预算基线对比、提取字段人工核验、引用支持标注和运行成本统计。另需验证两个受限检索源的真实凭据，以及可选语义 Embedding。当前的准确率、召回率、提升百分比均不预填。
